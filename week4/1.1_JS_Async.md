## Overview
* 초기 JS의 비동기: Callback-based 방식
* 해당 방식의 문제점인 Callback hell을 해결하기 위해 Promise 객체가 등장
* 코드 블럭의 깊이를 줄이는 데에는 성공했으나, then이 무한히 이어지는 Promise hell 문제가 대두됨
* 해당 문제를 해결하고 기존의 동기 코드처럼 비동기작업을 처리하기 위해 async-await 문법이 등장

## JS의 비동기 작업
- 실행중인 작업을 멈추지 않고 다음 작업을 병렬적으로 처리하는 것
- 서버와의 통신 등 오래 걸리면서, 메인 로직과 분리할 수 있는 로직은 분리하는 것이 성능 면에서 이점이 있다.
- JS는 기본적으로 싱글스레드 언어로 여러 작업을 동시에 할 수 없다.
  - 하지만, 언어 내부적으로 백그라운드 스레드를 사용하여 해당 스레드에서 Non-blocking IO/Request 등을 처리한다.

## `Promise` 객체
- JS는 비동기 작업 도중에서도 순차적으로 처리해야할 부분을 구현하기 위해 일종의 편법으로 콜백을 활용해왔다.
- 또한, 순차적으로 실행해야 할 기능을 늘어놓기 위해서 콜백 안에서 콜백을 사용하면서, 일명 "콜백 지옥"에 빠지는 문제가 있었다.
- 이를 해결하고 비동기 작업을 정식으로 지원하기 위해, 비동기 처리를 위한 전용 객체로 등장한 것이 `Promise` 객체이다.
- Promise 객체는 두 함수 `resolve`와 `reject`를 매개변수로 받는 함수를 객체로 Wrap해준 객체로 볼 수 있다.
  - 이 때, 함수 내부에서 return을 하고 싶다면 `return resolve({ return value });`를, 오류를 throw 하고 싶다면 `return reject({ error object });`의 형식으로 처리한다.

### `.then()` 메서드
- 비동기 처리가 필요한, 오래 걸리는 기능을 `Promise` 객체로 감싸고, 그 뒤에 순차적으로 처리할 기능들을 `.then()` 메서드의 연결로 늘어놓는다.
- 기존의 방식은 콜백 안에서 콜백함수를 정의하기에, 코드의 깊이가 점점 깊어지는 "콜백 지옥"이 발생하지만, `Promise`는 `.then()` 메서드의 체인으로 구성되어, 코드의 깊이가 무한히 깊어지는 문제를 해결할 수 있다.
- then 메서드는 Promise 클래스의 메서드로, Promise로 Wrap 되어있는 함수가 리턴값을 resolve하면 해당 값을 then 함수의 콜백함수에 매개변수로 넣어 실행하는 구조이다.
- then 메서드 자체는 Promise 객체를 리턴하므로, then 메서드를 계속 연달아 사용하는 체이닝이 가능하다.

### `.catch()` 메서드
- Promise 객체의 비동기 처리 중 발생한 오류를 처리하고 싶을 때 `.catch()` 메서드로 처리한다.
- Promise 객체의 실행중 예외 발생 여부는 고전적인 Promise-style로 실행되었을 때 `try-catch` 문에서 처리할 수 없다.
  - 일반적인 `throw`로 발생한 예외가 아닌, `reject` 콜백 호출로 인한 예외 발생이기 때문이다.
- 이를 Promise 객체 내에서 안전하게 처리하기 위해 `.catch()` 함수를 사용한다.
- 해당 메서드 또한 Promise 객체를 리턴하므로, then 메서드와 함께 catch 메서드를 체이닝할 수 있다.

### 예시 코드
```js
// ms만큼 기다리는 함수
function Timer(ms) {
  return new Promise(res => setTimeout(res, ms));
}

Timer(500)
  .then(() => console.log("500ms delay!"));
// Result: 500ms delay!
```

### Promise 객체의 상태
* Pending: Promise object가 만들어지고, 실행중인 상태
* Fulfilled: 오류 없이 실행이 완료된 상태 (resolve 함수 호출)
* Rejected: 실행중 오류가 발생한 상태 (reject 함수 호출)

### `Promise.all()` / `Promise.race()`
* `Promise.all()`: Promise object의 리스트를 받아 해당 promise가 모두 실행될 때까지 대기
  - 리스트로 전달받은 Promise의 resolve값을 순서대로 리스트로 만들어 return함
  - 실행 중 하나라도 reject된다면 reject됨
* `Promise.race()`: Promise obejct의 리스트를 받아, 그 중 가장 빠르게 실행이 끝난 object를 return함.
  - cf. `Promise.any()`: Promise object의 리스트를 받아, 그 중 가장 빠르게 `resolve`된 object를 return하거나, 모두 reject되었다면 해당 오류를 모은 `AggregateError`를 return함
    - `Promise.race()`는 `Promise.any()`와 달리 `reject`되어도 해당 object를 return함
  - 예시 코드
    ```js
    // ms만큼 기다리되, 5초 이상 걸리면 reject
    function Timer(ms) {
      const p1 = new Promise(res => setTimeout(res, ms)),
            p2 = new Promise((res, rej) => setTimeout(rej, 5000));
      return Promise.race([ p1, p2 ]);
    }

    Timer(500)
      .then(() => console.log("500ms delay!"))
      .catch(() => console.log("More than 5000ms?? It's 5 sec!!"));
    // Result: 500ms delay!
    ```

## async/await
- ES2017에 새로 등장한 문법
- Promise를 대체하는 것이 아닌, 단순한 Syntax Sugar
- 단순히 Promise 객체를 return하는 함수 앞에 `await`을 붙이고, 해당 키워드가 사용된 함수를 `function` 대신 `async function`으로 선언하면 끝
- 이 문법을 통해, 기존의 절차적 코드와 비슷한 형식으로 코드 작성 가능!
- 예시 코드
  ```js
  // ms만큼 기다리되, 5초 이상 걸리면 reject
  function Timer(ms) {
    const p1 = new Promise(res => setTimeout(res, ms)),
          p2 = new Promise((res, rej) => setTimeout(rej, 5000));
    return Promise.race([ p1, p2 ]);
  }

  (async () => {
    try {
      await Timer(500);
      console.log("500ms delay!");
    } catch {
      console.log("More than 5000ms?? It's 5 sec!!");
    }
  })();
  ```

### `await`으로 얻어온 값
* Promise가 resolve된 경우 (Promise의 status가 fulfilled인 경우)
  - resolve된 data를 그대로 return함.
* Promise가 reject된 경우 (Promise의 status가 rejected인 경우)
  - 해당 Error가 Promise.reject()로 wrap되어 return됨
